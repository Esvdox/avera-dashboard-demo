# ТЗ. Мобильный экран AVERA по референсу

## Уточнение. Парные плашки «Было / стало»

На фото первая пара ограничена примерно x=98–288 и x=301–491, y=553–652. При масштабе 390/425 это две плашки около 174 × 91 CSS px и зазор 12 px. В каждой три строки на одинаковой высоте. Подпись 12 px, число 18 px полужирным, контекст 11 px. Скругление 16 px, внутреннее поле 14 px. В AVERA название и единица вынесены в общий заголовок пары. Подписи «Было» и «Стало» занимают одну строку. Каждая пара использует одну сетку с равными колонками и фиксированными строками, сохраняемыми при НД. Слева период исходного значения, справа изменение только для сопоставимой пары. Из одного фото исходный CSS и JS не извлекаются. Переиспользовать токены AVERA и переключатель из comparison.js. Проверить равенство габаритов и координат всех трёх строк на 320, 390 и 1280 px.

Источник — утверждённое фото из личного навыка `sergey-dashboard`, `references/mobile-layout.jpg`. Растр 589 × 1280 px. Анализировать внутренний экран приложения приблизительно x=82–507, y=166–1091. Элементы iOS и просмотрщика за его пределами в интерфейс не входят. Геометрия ниже оценена по границам на растре. Рабочая ширина 425 px принята за 390 CSS px, коэффициент около 0,92. Исходный viewport и реальный CSS референса неизвестны.

## Что реализовать

- Системная шапка опирается на действующую оболочку проекта. Окончательные компоненты шапки и навигации требуют рабочего гида AVERA. Снимок задаёт геометрию. Цвета берутся из `tokens.css`.
- В обзоре сохранить две колонки KPI на телефоне. У каждой карточки короткая подпись, значение и одна строка контекста. Ряды выровнять по числам через общие строки сетки. Стандартные графики обзора остаются полноширинными на мобильном.
- В «Сравнении» собрать единый блок управления по образцу панели периода. Внутри переключатель «Было / стало» и «Графики», затем компактная строка контекста. В режиме цифр показать дату начала сравнения и расшифровку НД. В режиме графиков показать общую легенду прихода и сегодняшней даты. Временные интервалы KPI различаются, поэтому даты остаются рядом с соответствующим значением. Действия выбора произвольного периода появятся после подключения сопоставимых временных рядов.
- В «Было / стало» и «Графиках» каждая метрика занимает отдельную карточку на всю ширину. Это правило Сергея для парных значений имеет приоритет перед обзорной сеткой 2×2 из фото. Одинаковые заголовки, поля 14 px, радиус по токену, зазор 11–12 px. В обоих режимах один и тот же ряд содержимого 102 px. Цифры 18 px на общей горизонтали, период ниже, единица в заголовке.

## CSS и JS

- Проверенный целевой CSS: `design.css` задаёт шапку 58 px на мобильном, поле страницы 14 px и сетку KPI в две колонки. `comparison.css` задаёт сетку сравнений, общие строки значений и размеры графиков. Переиспользовать эти файлы и токены.
- Проверенный целевой JS: `comparison.js` строит карточки из `comparisonData()`, обрабатывает переключение кнопками `data-comparison-view` и восстанавливает фокус. Сохранить обработчик, маршрутизацию и шесть метрик. Дата «сегодня» рассчитывается по Москве. Линия прихода сплошная, линия сегодняшней даты тонкая и пунктирная. Пустые ряды показывают НД без фиктивных точек.
- Оригинальные CSS/JS референса недоступны. Правила компонентов восстановлены по снимку, поведение берётся из контракта AVERA. Источники остаются прежними: ОФР, данные 1С о текучести и утверждённый стартовый перечень SKU. Методика и решения остаются в раскрывающихся блоках.

## Приёмка

Проверить 320, 390 и 1280 CSS px в обеих темах. Панель управления расположена до карточек. На 390 px боковые поля около 14 px, карточки обзора стоят по две в ряд, графики обзора на всю ширину. В «Сравнении» шесть карточек в каждом режиме, исходное и текущее значения стоят на одной высоте, у каждой пары одинаковая высота. Страница не прокручивается горизонтально. Кнопки доступны с клавиатуры, фокус сохраняется, данные и статусы НД совпадают с текущими источниками.
