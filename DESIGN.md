# Визуальный стандарт дашбордов

Основание: десять мобильных референсов, выбранных пользователем 30 октября 2026 года. Использовать их геометрию, плотность, иерархию, типографику и логику навигации в следующих дашбордах. Точное повторение цветового решения запрещено пользователем.

## Геометрия и типографика

Размеры восстановлены по изображениям, а не извлечены из исходного CSS. Увеличенные пиксели скриншота нельзя приравнивать к CSS-пикселям. На ширине около 390 CSS px использовать следующие ориентиры:

| Элемент | Размер |
|---|---|
| Шрифт | Системный: -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif |
| Основной текст | 14 px, line-height 1.45 |
| Подписи и поля показателей | 12 px |
| Метаданные и легенды | 11–12 px, без уменьшения ради размещения |
| Заголовок блока | 15 px, вес 650 |
| Заголовок страницы | 23–24 px, вес 700 |
| Значение KPI | 18 px на телефоне, 19 px на компьютере, вес 700 |
| Иконки KPI | 16 px, контурные |
| Иконки действий | 18 px; навигация 20 px |
| Иконка в крупной плитке | 28 px, если такая плитка нужна |
| Внешнее поле телефона | 14 px |
| Промежуток KPI | 11–12 px |
| Внутреннее поле карточки | 14–16 px |
| Скругление карточки | 16 px |
| Скругление поля и кнопки | 12 px |
| KPI | Две колонки на телефоне, минимальная высота около 100 px; текст может увеличивать её |
| График | Около 210 px высотой на телефоне; отдельная карточка с заголовком и легендой |
| Точки касания | Не менее 40–44 px для основных мобильных действий |

Точный исходный шрифт по снимкам не установлен; на iOS системный стек даёт системный шрифт Apple. Размер шрифта полей на сенсорном устройстве — минимум 16 px, чтобы Safari не увеличивал страницу при вводе. Масштабирование пользователем разрешено.

## Компоновка

На компьютере: боковая навигация, компактная верхняя панель, затем фильтры/сравнение, KPI и графики. На телефоне: верхняя панель с меню, выдвижная боковая навигация, KPI в две колонки, графики и формы в одну. Меню закрывается по выбору раздела, Escape или касанию фона и возвращает фокус.

Карточки самостоятельные, со светлой границей и очень мягкой тенью. Не объединять KPI в один сплошной прямоугольник с разделительными линиями. Не увеличивать ключевые цифры до рекламного размера. Длинные строки переносятся; широкие таблицы прокручиваются внутри блока. Не добавлять ложные уведомления, пользователей, часы или неработающие фильтры только ради сходства с изображениями.

Из референсов берётся логика формы: связанные поля объединены в короткие блоки, действие находится рядом с относящимися к нему данными. Настройки, если появятся, группируются по смыслу, переключатели размещаются справа. Крупные цветные плитки допустимы для выбора модулей, но не заменяют аналитические карточки.

## Новые цвета

По последнему указанию пользователя использовать исходные цвета системы AVERA, извлечённые из styles.css первоначального прототипа. Предложенная petrol / sage / copper палитра отклонена.

Светлая тема: фон #f5f9fd, карточки #ffffff, текст #081633, вторичный текст #617594, границы #dce8f6, акцент #0759ef. Тёмная: фон #051428, карточки #0b1e36, текст #f4f7ff, вторичный текст #a8bcd7, границы #203c5e, акцент #02c4ee. Успех — #14785e / #75dbc0. Цвета исходной AVERA не означают возврат прежней геометрии: размеры и компоновка остаются по мобильным референсам. Не копировать фиолетовую палитру сторонних референсов. Семантика риска сохраняет отдельный читаемый цвет и текстовую подпись.

Цветовые роли и размеры заданы в tokens.css. design.css использует эти роли. Новые компоненты используют те же токены. Переключение темы едино для всех шести разделов, выбор сохраняется.

## Проверка

После изменения общих токенов проверять 390 и 1280 px, светлую и тёмную темы, переходы по всем разделам, возврат, историю браузера и обновление страницы. На 320 px не допускается горизонтальная прокрутка всей страницы. Скриншоты сравниваются с референсом по пропорциям; реальные данные и бизнес-логика не меняются ради оформления.

Эмуляция не подтверждает поведение физического iPhone: системные меню выбора, клавиатуру, safe area и поведение браузерной панели следует оценить на устройстве. Системные меню не рисуются вручную поверх нативного select.
